**Implementation:** Added `WorkspaceCapabilityRegistry`, owned only by one `OAuthReadOnlyMcpRuntime` instance. Its public handle remains `ws_<32 lowercase hex>` generated from 128 random bits and is never derived from a path. Records are indexed by handle and by `(principalDigest, workspaceKey, policyRevision)` for same-principal/root/policy deduplication. The OAuth capability principal is the exact tuple `deployment binding + incarnation + ownerRef + clientRef + resource + grantId + grantRevision`; `policyRevision` is a separate validity epoch. Transport session ID, access-token ID/fingerprint, refresh generation, path, `workspaceKey`, and default root are not continuity authority. The registry has sliding TTL, bounded tombstones, exact-principal list/resolve/close, non-destructive foreign misses, policy-stale invalidation, shared revocation-event fan-out, 64 active records per principal, 256 per runtime, and no live-record eviction. Runtime `dispose()` intentionally destroys all configured-root capability state, so service restart remains fail-closed.

`WorkspaceManager` now acts as a facade over the shared registry only when explicitly injected. Its historical private manager remains the default backend. Configured-root open/get/close/list use the shared registry in OAuth cross-transport mode; confirmed-root and task-worktree authorities remain separate and are never inserted into the shared backend. Shared semantic binding/authority digests use the principal digest plus a stable cross-transport marker instead of a transport ID. Each transport manager subscribes to shared revocation events so `close_workspace`, TTL, and policy invalidation fan out to semantic/cache observers; transport/server disposal unsubscribes that observer without revoking the shared capability.

`createCodexGPTServer` fails closed unless shared registry and principal source are configured together, and rejects the pair unless `authMode === "oauth"`. `productionRuntime` threads the dependency but never creates it. `OAuthReadOnlyMcpRuntime` is the sole runtime instantiation site, creates one registry per running deployment runtime, derives the principal from the already verified request-local OAuth context on every tool request, injects the same registry into every per-transport production server, prunes it with runtime maintenance, and disposes it on runtime shutdown. This is intentionally not a module-global/process-global registry.

A disposal-seam review found that OAuth transport `onclose` may call `disposeProductionCodexGPTServer(server)` without first invoking the server's `close()` wrapper. Added `disposeCodexGPTServerLocalState(server)` and made the production disposer call it, so transport rotation cannot retain obsolete `WorkspaceManager`/semantic subscriptions while still leaving the shared configured-root capability live. This fixes resource ownership without turning transport close back into capability revocation.

Added `CODEXGPT_OAUTH_WORKSPACE_CAPABILITY_MODE=oauth_cross_transport|session_local`. The default is `oauth_cross_transport`; `session_local` is the one-cycle OAuth rollback path. Legacy/query-token and STDIO do not receive the shared dependency regardless of this setting. The server model instructions were also corrected: OAuth ChatGPT Web/App is now explicitly told to reuse the returned `workspace_id` after MCP transport rotation and never replace an explicitly opened non-default root with omitted/default-workspace resolution. Session-local legacy/query-token/STDIO guidance retains its historical omitted-ID compatibility instruction. `close_workspace` descriptor wording now says opaque capability rather than session-scoped handle; tool names, schemas, counts, direct/supertool result payloads, and OAuth scopes remain unchanged.
